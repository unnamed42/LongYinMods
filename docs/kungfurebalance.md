# 功法数值再平衡 —— 按 mod 既有规则给新增功法（id 996–1050）定值

> 归属：[`AGENTS.md`](../AGENTS.md) §7 索引有一行指向本文件；数据与脚本在 `KungFuRebalance/`。
> **读者**：要改 `KungfuSkillData.csv` 数值、或给游戏更新新增的功法补平衡的人。
> 反编译/原生 hook 的手法**不**在这里，去 [docs/decompilation.md](decompilation.md) /
> [docs/native-hooks.md](native-hooks.md)；游戏机制的通用探查去 [docs/game-internals.md](game-internals.md)。

---

## 0. 判据速查（只想知道「能不能这么做」就读这一节）

- **改功法表只动 7 个数值列**：`基础威力 / 威力系数 / 修炼需求 / 修炼效果 / 运功效果 / 使用特效 / 内力消耗`。
  其余 22 列（描述 / 攻击范围 / 子弹 / 架势 / 隐藏…）**一个都别动** —— 脚本靠「与原版行逐字节比对」来保证这点。
- **两个战力口径，别混用**：
  - 外功（拳掌/剑法/刀法/长兵/奇门/射术）→ `KungfuSkillLvData.GetSkillFightScore()`；
  - 内功/轻功/绝技 → `HeroSpeAddData.GetValue()`（它们 `GetSkillFightScore()` 恒为 0）。
- **"对标同类别同等级老功法的取值区间"是验收标准**，不是"看着差不多"。跑 `rebalance_new_skills.py` 末尾自检，越界条数必须为 0。
- ⚠️ **`威力系数` 里的分隔符只能是 `;`**。写成 `,` 会让游戏**静默丢弃**后面所有系数（真实案例见 §5）。
- ⚠️ 游戏内存里有 id **1051–1059** 的隐藏"太祖"系列，**不在导出表里**（另一个 mod 加的），忽略。
- ⚠️ **别信"公式能完全复现"**：作者的改造是"公式打底 + 逐条手调"，`基础威力` / 内功血量这类列有 1~2 成的手工噪声，只能做到**落在同组区间内**。

## 1. CSV ↔ 游戏字段

`KungfuSkillData.csv` 是 UTF-8 **带 BOM** + **CRLF**，29 列，列名就是游戏 `KungfuSkillData` 的字段：

| CSV 列 | 字段 | CSV 列 | 字段 |
|---|---|---|---|
| 基础威力 | `baseDamage` | 使用特效 | `useAddData` |
| 威力系数 | `addDamageRatio` | 运功效果 | `equipAddData` |
| 内力消耗 | `manaCost` | 修炼效果 | `upgradeAddData` |
| 经验系数 | `expRatio` | 修炼需求 | `skillNeeds` |
| 等级 | `rareLv` | 所属势力 | `belongForceID` |

**等级 = 稀有度**：`0 白 / 1 绿 / 2 蓝 / 3 紫 / 4 顶级 / 5 绝世`。
（作者原话"紫色以上"精确对应代码里的 L3+，"绝世及顶级外功"对应 L4/L5。）

`addDamageRatio` / `skillNeeds` 是 `AttriNumData`，**下标是固定顺序**：

| 数组 | 下标含义 |
|---|---|
| `attri[6]` | `[力道, 灵巧, 智力, 意志, 体质, 经脉]` |
| `fightSkill[9]` | 下标 = **类别序号**：`[内功,轻功,绝技,拳掌,剑法,刀法,长兵,奇门,射术]` |
| `livingSkill[9]` | 医术/毒术/锻造… |
| `Hp` / `Mana` | `生命上限` / `内力` 系数 |

> 这条映射是**反推出来的**（用只含单一属性的功法对照下标），不是文档里写的。

## 2. mod 既有规律（按列 × 等级）

规律来源：对 `KungfuSkillData.csv`（996 行）与 `Vanilla_KungfuSkillData.csv`（1051 行）
做逐列 diff 得出。**L0/L1/L2 大部分列不动**，改动集中在 L3+。

| 列 | L0 | L1 | L2 | L3（紫） | L4（顶级） | L5（绝世） |
|---|---|---|---|---|---|---|
| 威力系数 | – | 每属性 +1 | +1 | +1 | +2 | +2~4 |
| 基础威力（外功） | – | **+4 固定** | – | ≈×1.53~1.57 | ≈×1.89 | ≈×2.82 |
| 内力消耗（外功） | – | – | – | 按内力系数 ×1.5~3 | ×1.9~5.9 | ×4~15 |
| 使用特效 | – | – | +真伤0.1 | +真伤0.15、+命中 | +内劲、+真伤、+命中 | +真伤、+命中、+连击−、+内劲 |
| 运功效果（外功） | – | – | – | – | **从空新建**，总量≈4~5 | **从空新建**，总量≈10 |
| 运功效果（内功） | 生命/内力 ×2 | ×2 | ×2 + 体力上限40 | ×3~4 + 体力上限60 + 自愈/护体/负面抗性 | ×4~5 + 体力上限80 | ×4~5 + 体力上限100 |
| 修炼需求 | – | – | +10 | +20 | +20 | +20~40 |
| 修炼效果（内功） | – | +生命4/内力4 | … | +小被动 | +生命10~14/内力6~10/负面抗性0.0075 | +生命16~20/内力12~16/负面抗性0.01 |

几条**容易漏**的：

- **"4 级以上内功加词条"**：L4 平均 +3.9 条、L5 +4.9 条，且 `体力上限` **人人都有**，
  其次 `负面抗性 / 自愈 / 回内 / 护体真气`。
- **L5 绝技的运功效果属性值统一 +2**（12→14，数据里出现 20 次），漏了会让绝技战力明显偏低。
- **"无内力系数就不给内劲"**：`威力系数` 里没有 `内力` 的外功，mod 一律不加 `内劲` 词条。
- **"下调了部分内功加成"**：全表只下调了 4 处（外伤 0.1→0.05、回血、吸内、反伤吸内），是针对性 nerf，不是通则。

## 3. 两个战力口径

### 3.1 外功：`KungfuSkillLvData.GetSkillFightScore()`

`new KungfuSkillLvData(skillID)` 即可构造任意功法的实例（`lv=0`），**与角色属性无关** —— 拿它当"功法自身强度"的客观标尺。
返回值只在外功上有意义（内功/轻功/绝技恒 0）。

### 3.2 内功/轻功/绝技：`HeroSpeAddData.GetValue()`

游戏给「运功效果 / 修炼效果」折算战力分用的就是它。**逐键实测**出的权重表（`<键>1` → `GetValue`）：

| 权重 | 键 |
|---|---|
| **1.0 / 点** | 全属性（力道…经脉）、全武学（拳掌…射术）、生活技能、所有 `XX潜力`、`击退`、`装备负重` |
| 0.5 / 0.25 / 0.2 | `生命上限` / `内力上限` / `体力上限` |
| 2.0 | `护甲` / `减伤` / `自愈` |
| 5.0 | `移距` / `回体` |
| 25 / 50 | `削内`｜`护体真气` / `吸内` / `反伤吸内` / `药性` |
| **100 / 点** | 绝大多数特效（`真伤`/`命中`/`眩晕`/`破甲`…）、`负面抗性`；`连击-` 为 **−100**（所以它是**减益**） |
| 200 | `无敌` / `反弹` |
| **0** | **`抗耐药性`**（白给）；`回内` 666.7、`回血` 1000（量级不同，注意单位） |

> 这套表已固化在 `rebalance_new_skills.py` 的 `SPE_W` 里，**离线就能自检**，不必连游戏。

## 4. 工作流

```bash
cd KungFuRebalance
python3 rebalance_new_skills.py      # 读两组 csv，产出 KungfuSkillData_v2.csv + rebalance_review.tsv
```

脚本末尾会打印**运功效果战力分自检**（每组老功法区间 vs 新功法），`越界条数: 0` 才算过。

外功的 `GetSkillFightScore` 校准**必须连游戏**（分数是原生函数算的），做法：

1. 起游戏 + MCP server；
2. 用 `execute_csharp` 读 `Z:\...\KungfuRebalance\KungfuSkillData_v2.csv`；
3. 把各行写回 `GameDataController.kungfuSkillDataBase`（`baseDamage` / `manaCost` /
   `addDamageRatio = StringToAttriRatio(威力系数)` / `equipAddData = StringToSpeAddData(运功效果)` …）；
4. `new KungfuSkillLvData(id).GetSkillFightScore()` 逐条打分，与同类别同等级的老功法比区间；
5. 越界的按 `目标区间中位 / 当前分` 反解 `基础威力`，迭代到落回区间；
6. 把结果钉进脚本的 `CALIB_BASE`；
7. **把这批值和原版值都灌回去**（我们是改内存，不是改存档），收尾时恢复原版。

> 灌内存前务必确认目标文件路径；MCP 的 `execute_csharp` 里游戏侧路径是 `Z:\` 开头的 Wine 映射。

## 5. 已知坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **`威力系数` 里混入 `,`** | 游戏只解析到逗号前的部分，**静默丢弃后面所有系数**。原版 `id=662 伏魔铲法` 是 `意志1;奇门2,内力0.1`，实际只有 `意志1`，`奇门2`/`内力0.1` 全没了 | mod 表已修（`意志2;奇门3;内力0.1`）；**改表后务必扫一遍逗号** |
| 隐藏"太祖"系列 | 游戏内存有 id 1051–1059，导出表没有 | 另一个 mod 加的，**忽略** |
| `GetSkillFightScore()` 对非外功返回 0 | 直接拿来比会以为内功"没战力" | 内功/轻功/绝技改用 `GetValue()` |
| 空字符串喂解析器 | `StringToAttriRatio("")` 抛 `Il2CppException` | 空字段要显式给 `new AttriNumData()` / `new HeroSpeAddData()` |
| 战力校准改的是**活进程内存** | 不落盘，但会影响当前这局战斗 | 收尾灌回原版；重启游戏也会恢复 |
| 作者的改造有手工噪声 | 同原值可能得到两个不同结果（如 L3 基础威力 10→16/18/22） | 别追求逐行复现，**对齐区间**即可 |
